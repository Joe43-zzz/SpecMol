# SpecMol + 3D 信息融合实验整理

整理日期：2026-05-08  
当前主线：BACE 上评估 Uni-Mol 3D 信息能否改善 SpecMol 风格分子性质预测。

---

## 1. 总体目标

这个项目的核心问题是：

> 在原始 SpecMol 的 2D 分子图 + 分子指纹框架中，引入 3D 信息是否能提升分子性质预测？

原始 SpecMol：

```text
SMILES
  |
  +-- 2D 分子图 -> GNN / ChebNet II
  |
  +-- 分子指纹 -> MLP
  |
  v
拼接表示 -> 下游性质预测
```

当前关注 BACE。原因是 BACE 已经有 Uni-Mol scaffold fold、SDF、pair representation，可以做较完整的 V0 / 3D / 消融比较。

---

## 3. BACE Fair Baseline

### 3.1 目的

重新跑原始 SpecMol baseline，保证它和 3D 版本使用同一个 split。

之前的问题：

```text
旧 baseline:
  DeepChem scaffold split

3D 版本:
  Uni-Mol scaffold fold split
```

这两个 split 不一致，不能直接比较。因此补了 Uni-Mol fold split 下的 baseline。

### 3.2 实验设置

| 项目 | 设置 |
|---|---|
| Dataset | BACE |
| Split | Uni-Mol scaffold fold split |
| Metric | ROC-AUC，越高越好 |
| Pretrain seeds | 9, 19, 29 |
| Eval seeds | 9, 19, 29 |
| 汇总 | 3 pretrain seeds x 3 eval seeds = 9 个 AUC |

### 3.3 相关文件

| 文件 | 作用 |
|---|---|
| `make_baseline_unifold.py` | 用 Uni-Mol fold split 重建 2D-only BACE `.pt` 数据 |
| `run_baseline_unifold.py` | 跑 V0 GNN+FP 和 FP-only |
| `baseline_unifold_results.json` | 保存结果 |
| `down_task_unifold/processed/bace_*.pt` | fair baseline 使用的数据 |

### 3.4 结果

| 实验 | 含义 | AUC mean ± std |
|---|---|---:|
| V0 GNN + FP | 原始 SpecMol baseline | 0.797 ± 0.085 |
| FP-only | 只用分子指纹，不用 GNN | **0.846 ± 0.010** |

### 3.5 观察

FP-only 明显高于 GNN+FP，说明在 BACE 上：

```text
分子指纹本身很强；
GNN 分支可能没有稳定正贡献；
后续必须补 GNN-only 才能判断 GNN 本身是否有效。
```

## 4. BACE 静态 3D 边权实验

### 4.1 目的

将 Uni-Mol 的 3D pair representation 注入 SpecMol。

设计原则：

```text
不改变图拓扑；
只给原始化学键生成 edge_weight；
用带权 Laplacian 替代原始等权 Laplacian。
```

核心链路：

```text
Uni-Mol pair_repr
        |
        v
PairToEdgeWeight
        |
        v
edge_weight
        |
        v
weighted Laplacian
        |
        v
ChebNet II
```

### 4.2 核心代码改动

#### 4.2.1 数据接入

文件：`make_bace_from_unimol.py`

核心函数：

```python
attach_unimol_pair_to_data(data, atoms, pair_payload)
```

作用：

```text
读取 Uni-Mol encoder_pair_rep；
筛选当前分子对应的原子；
构造全原子对 pair_edge_index；
保存 pair_repr_edge；
保留原始化学键 edge_index。
```

关键字段：

| 字段 | 含义 |
|---|---|
| `edge_index` | 原始化学键边，GNN 仍沿这些边传播 |
| `pair_edge_index` | 全原子对索引 |
| `pair_repr_edge` | Uni-Mol 对每个原子对输出的 64 维 pair representation |

#### 4.2.2 pair_repr -> edge_weight

文件：`pair_to_edge_weight.py`

核心类：

```python
class PairToEdgeWeight(nn.Module)
```

逻辑：

```text
对每条化学键 (i, j):
  1. 找 pair_repr(i, j)
  2. 找 pair_repr(j, i)
  3. 两个方向分别过同一个 MLP
  4. 平均两个方向的 raw score，保证化学键权重对称
  5. sigmoid 得到 edge_weight
```

MLP：

```text
64 -> 32 -> 1
```

初始化：

```text
bias = +5
sigmoid(5) ≈ 0.993
```

意义：

```text
训练初始时 edge_weight 接近 1；
模型起点接近原始 V0；
避免一开始就大幅改变图结构。
```

#### 4.2.3 接入模型

文件：`model_gnn_pre_v2.py`

核心类：

```python
class LH_Direct_V2(nn.Module)
```

作用：

```text
从 data 中读取 pair_repr_edge、pair_edge_index、edge_index；
调用 PairToEdgeWeight 得到 edge_weight；
high-pass 和 low-pass 两个 ChebNet 分支都使用这个 edge_weight。
```

#### 4.2.4 带权 Laplacian

文件：`LH_Direct_ChebnetII_prop_v2.py`

核心逻辑：

```python
get_laplacian(
    edge_index,
    edge_weight=edge_weight,
    normalization='sym',
)
```

作用：

```text
原始 ChebNet II: edge_index -> 等权 Laplacian
V2 静态 3D: edge_index + edge_weight -> 带权 Laplacian
```

### 4.3 实验设置

| 项目 | 设置 |
|---|---|
| Dataset | BACE |
| Split | Uni-Mol scaffold fold split |
| Metric | ROC-AUC |
| Pretrain seeds | 9, 19, 29 |
| Eval seeds | 9, 19, 29 |
| 数据目录 | `down_task_v2` |

### 4.4 相关文件

| 文件 | 作用 |
|---|---|
| `make_bace_from_unimol.py` | 构造带 Uni-Mol pair_repr 的 BACE 数据 |
| `pair_to_edge_weight.py` | pair_repr -> edge_weight |
| `model_gnn_pre_v2.py` | V2 模型入口 |
| `LH_Direct_ChebnetII_prop_v2.py` | 带权 ChebNet II 传播 |
| `run_v2_t5_bace.py` | 运行 BACE 静态 3D 实验 |
| `v2_t5_bace_results.json` | 保存结果 |

### 4.5 结果

| 实验 | AUC mean ± std |
|---|---:|
| V0 GNN + FP | 0.797 ± 0.085 |
| 静态 3D GNN + FP | 0.837 ± 0.009 |
| FP-only | **0.846 ± 0.010** |

### 4.6 观察

静态 3D 版本：

```text
比 V0 均值更高；
比 V0 稳定；
但没有超过 FP-only。
```

另外，`PairToEdgeWeight` 的 bias 从 5.0 只降到约 4.84：

```text
sigmoid 后 edge_weight 仍接近 0.99；
说明 learned edge_weight 可能没有充分拉开差异。
```

## 5. BACE Nullify 消融

### 5.1 目的

检查 learned edge_weight 是否真的有效。

做法：

```text
保留 V2 模型结构；
但强制 edge_weight = 1。
```

也就是说：

```text
PairToEdgeWeight 仍存在；
但 forward 时返回全 1 边权；
等价于不使用 learned 3D edge_weight。
```

### 5.3 当前结果

| 实验 | AUC |
|---|---:|
| Nullify, seed 9 only | 0.879 |

当前只完成：

```text

```

未完成：

### 5.4 观察

## 6. T6 动态更新设计

### 6.1 目的

静态版本只做：

```text
pair_repr -> edge_weight -> GNN
```

T6 想做：

```text
pair_repr -> edge_weight -> node state -> update pair_repr
```

也就是：

```text
pair 影响 node；
node 再反过来更新 pair。
```

### 6.2 核心设计

在 ChebNet 的第 k 步传播后，得到节点状态 `T_k`。

对每个原子对 `(i, j)`：

```text
Q_i = W_Q T_i
K_j = W_K T_j
score_ij = Q_i · K_j / sqrt(d)
delta_ij = out_proj(score_ij)
pair_repr_ij = pair_repr_ij + delta_ij
```

注意：

这里是 attention-style 的 Q/K 打分，不是完整 self-attention。

没有：

```text
softmax；
value V；
多头 attention 聚合。
```

它只是用当前节点状态估计原子对关系变化。

### 6.3 相关文件

| 文件 | 作用 |
|---|---|
| `node_to_pair_update.py` | `NodeToPairUpdate`，用节点状态更新 pair_repr |
| `LH_Direct_ChebnetII_prop_v2.py` | 把 node-to-pair 更新嵌入 Chebyshev K-step |
| `model_gnn_pre_v2.py` | 通过 `t6=True` 打开动态路径 |
| `run_v2_t6_sanity.py` | T6 sanity check |
| `run_v2_t6_micro_sanity.py` | 小规模 sanity check |

### 6.4 当前状态

```text
有代码；
有 sanity check；
没有正式 BACE 实验结果。
```

因此不能把 T6 当作当前性能结论，只能作为后续方法方向。

## 7. FreeSolv 补充实验

### 7.1 目的

看 3D 边权注入在更依赖 3D 构象的任务上是否有信号。

### 7.2 注意事项

FreeSolv 的 3D 来源不是 Uni-Mol。

它使用的是：

```text
RDKit 3D conformer distance
  -> GBF expansion
  -> 64 维 pair_repr
```

所以它不能直接证明：

```text
Uni-Mol 3D 在 BACE 上有效。
```

只能作为：

```text
3D 边权注入可能有潜力的旁证。
```

### 7.3 相关文件

| 文件 | 作用 |
|---|---|
| `prepare_freesolv_data.py` | 构造 FreeSolv 2D 和 3D 数据 |
| `run_freesolv_baseline.py` | FreeSolv 2D baseline |
| `run_freesolv_v2t5.py` | FreeSolv 静态 3D 版本 |
| `launcher_freesolv.py` | 批量运行 FreeSolv |
| `freesolv_baseline_results.json` | baseline 结果 |
| `freesolv_v2t5_results.json` | 3D 结果 |

### 7.4 结果

FreeSolv 是回归任务，指标 RMSE 越低越好。

| 实验 | RMSE mean ± std |
|---|---:|
| 2D baseline | 0.760 ± 0.047 |
| 静态 3D 版本 | **0.675 ± 0.033** |

### 7.5 观察

FreeSolv 上 3D 版本明显好于 2D baseline。

但由于 3D 来源不同，它适合作为补充现象，不适合作为 BACE + Uni-Mol 的直接证据。

## 9. 需要学姐决策的问题

这些不是单纯“下一步做什么”，而是路线选择问题。

### 9.1 BACE 还要不要继续深挖 GNN？

依据：

```text
FP-only > GNN+FP
FP-only > 静态 3D GNN+FP
```

需要学姐判断：

> BACE 上是不是 fingerprint 已经太强，GNN 分支本身不适合作为主要提升点？

可能决策：

```text
A. 继续在 BACE 上深挖 GNN，先补 GNN-only；
B. BACE 作为分析案例，不把它作为正向提升 story；
C. 转向更依赖 3D 的任务。
```

### 9.2 Nullify 是否优先补全？

依据：

```text
Nullify seed 9 = 0.879
静态 3D = 0.837 ± 0.009
```

需要学姐判断：

> 是否优先补完 nullify seeds 19 和 29？

如果补完仍然高，需要讨论：

```text
PairToEdgeWeight 是否设计过弱或过保守；
bias=+5 是否让 edge_weight 长期处于饱和区；
是否需要看 edge_weight 分布，而不是只看最终 AUC。
```

### 9.3 T6 动态更新是否值得现在推进？

依据：

```text
T6 更复杂；
静态 3D 尚未超过 FP-only；
learned edge_weight 是否有效还不清楚。
```

需要学姐判断：

> 是现在推进 T6，还是先完成 GNN-only / nullify 这些低成本消融？

当前建议：

```text
先补低成本消融；
如果 GNN-only 和 nullify 支持继续做，再推进 T6。
```

### 9.4 FreeSolv 是否可以作为 story 支撑？

依据：

```text
FreeSolv 3D 版本 RMSE 明显下降；
但它不是 Uni-Mol pair_repr。
```

需要学姐判断：

> FreeSolv 是作为补充现象轻轻带过，还是作为后续 3D-sensitive 任务方向？

### 9.5 最终路线选哪一种？

可以给学姐三个路线选项：

| 路线 | 核心 story |
|---|---|
| A. BACE 分析型 | 重点分析为什么 3D 没超过 FP-only，拆 GNN 和 edge_weight |
| B. 3D-sensitive 任务型 | 找 FreeSolv / ESOL / Lipophilicity 等更依赖 3D 的任务 |
| C. 方法型 | 从静态 edge_weight 推到 T6 动态 pair update |

目前更稳的建议：

```text
短期：补 BACE GNN-only 和 nullify；
中期：根据结果决定是否推进 T6；
长期：考虑加入更 3D-sensitive 的任务作为正向 story。
```
